# Obtener ayuda con rostemplate

Antes de abrir una incidencia, prepara un ejemplo mínimo reproducible y
revisa los canales de asistencia disponibles.

## Crear un reprex

Empieza por crear un ejemplo mínimo reproducible, o
[**reprex**](https://reprex.tidyverse.org/). Consulta [¡Obtén
ayuda!](https://www.tidyverse.org/help/) para obtener más indicaciones.

## Dónde preguntar

Cuando tengas preparado el **reprex**, decide [dónde
preguntar](https://www.tidyverse.org/help/#where-to-ask).

- Para consultas, empieza en [**Posit
  Community**](https://community.rstudio.com/) o [**Stack
  Overflow**](https://stackoverflow.com/), donde más personas podrán
  ayudarte.
- Para errores, [abre una
  incidencia](https://github.com/rOpenSpain/rostemplate/issues/new).
- Si tienes dudas, pregunta a la comunidad. Si el problema es un error o
  una solicitud de funcionalidad, puedes volver aquí para comunicarlo.

Antes de abrir una incidencia, [busca en las incidencias y los pull
requests](https://github.com/rOpenSpain/rostemplate/issues) para
comprobar que el error no se haya comunicado o corregido ya en la
versión de desarrollo. La búsqueda incluye por defecto
`is:issue is:open`. Puedes [editar los
calificadores](https://help.github.com/articles/searching-issues-and-pull-requests/)
según sea necesario, por ejemplo, `is:pr` o `is:closed`. Elimina
`is:open` para buscar en todas las incidencias del repositorio, tanto
abiertas como cerradas.

## Qué ocurre después

La comunidad de **rOpenSpain** mantiene **rostemplate** de forma
voluntaria, por lo que la respuesta puede tardar. Las personas
responsables pueden atender las incidencias por lotes, lo que también
puede retrasar la respuesta. Un buen **reprex** es especialmente
importante porque permite investigar el problema cuando haya
disponibilidad. Si no podemos reproducir un error, no podemos
corregirlo.
